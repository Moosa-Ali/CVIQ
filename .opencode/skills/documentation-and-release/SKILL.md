# Documentation And Release

Write durable records under `docs/engineering/` through documentation-scribe. Include date, request, scope, decision, affected files, test commands, browser evidence, known risks, and follow-up work.

Do not claim a test passed without output or a browser flow passed without evidence. Keep `docs/SRS.md` and `docs/design.md` authoritative for existing requirements; link to them rather than silently contradicting them.
